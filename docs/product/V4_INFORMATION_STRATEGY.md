# OrbitAI V4 信息策略

类别：产品方向

状态：原信息策略已由用户审核确认；自 2026-07-10 起，作为“可追溯的 AI 动态产业档案”的材料采集子策略继续有效。

方向更新：V4 不再以观点卡片作为唯一产品中心。公开事实、信息源注册表和观点卡片将进入事件档案，服务于产业、企业、人物和关键事件时间线。总体路线见 `docs/product/ORBITAI_ROADMAP.md`；该路线图已经用户审核确认，是后续 V4 开发的正式方向依据。

这份文档把 V4 的产品方向转化为可执行的信息采集策略。后续选择信息源、设计数据库字段、编写观点提取提示词、建设观点库页面时，应优先参考这里的边界。

## 范围

V4 先聚焦四个深度绑定的产业方向：

- AI Agent 与软件自动化
- 大模型基础设施、算力与芯片
- 人形机器人与具身智能
- AI 与硬件、终端和生产力工具

目标不是覆盖所有 AI 新闻，而是收集更少但更高价值的材料，帮助用户建立可长期积累的产业判断系统。

## 两类材料

OrbitAI 应明确区分“公开事实”和“高质量观点”。这两类材料都重要，但用途不同。

公开事实用于回答：

- 发生了什么？
- 谁参与了？
- 什么时候发生？
- 哪些能力、价格、供给、组织或市场状态发生了变化？
- 有什么证据或来源支撑？
- 未来能否被重新验证？

高质量观点用于回答：

- 谁提出了判断？
- 他或机构具体判断了什么？
- 这个判断背后的依据和推理是什么？
- 它属于哪个产业议题和分析维度？
- 是否包含时间范围、前提条件或预测？
- 后续能否与其他观点比较，或被现实验证？

## 需要收集的公开事实

优先收集能追溯到原始或半原始来源的事实：

- 产品发布和重大版本更新。
- 模型、芯片、机器人、设备或平台的能力变化。
- 价格、成本、供给、吞吐量、基准测试或性能变化。
- 企业公告、客户部署、订单、交付和商业化进展。
- 财报、资本开支、收入结构和业绩指引。
- 融资、并购、合作和战略投资。
- 招聘信号、团队变化、实验室成立和组织调整。
- 政策、出口管制、安全、标准和监管更新。
- 论文、技术报告、开源项目和代码仓库。
- 生产、供应链、制造工艺和关键零部件可获得性信号。

V4 中每条事实材料应尽量保留：

- 来源标题和 URL。
- 发布方或原始机构。
- 发布时间。
- 相关公司、人物、机构和主题。
- 提取出的事实陈述。
- 证据片段或支撑数据。
- 可信度或验证状态。

## 获取方式

V4 应采用分层获取策略，但实现上不应把它们做成互相割裂的四套系统。

核心原则：

> 信息源注册表是核心，RSS 抓取只是信息源的一种获取入口。后续 YouTube 链接、播客、财报电话会、论文、GitHub release、手动录入等，也都应作为同一个信息源注册表下的不同获取方式逐步补充。

也就是说，OrbitAI 应先回答“这个来源是谁，为什么值得长期关注”，再记录“可以通过哪些入口获取它的材料”。

### 第一层：沿用现有 RSS 流程

继续把当前 RSS 管线作为最低摩擦的信息采集入口。RSS 不应被理解为独立于信息源注册表之外的另一套来源系统，而应挂在具体来源下面。

适合 RSS 的来源包括：

- 新闻网站。
- 带 RSS 的公司博客。
- 研究机构博客。
- 技术博客。
- 有价值的 GitHub release feed。

### 第二层：策划式信息源注册表

新增一份 V4 信息源注册表。它是 V4 信息获取的主结构，用于管理 OrbitAI 到底长期关注谁、为什么关注、关注哪些议题，以及每个来源有哪些可用入口。

每个信息源未来应尽量包含：

- 名称。
- 类型：人物、公司、实验室、投资人、分析师、媒体、论文来源、代码仓库等。
- 主要主题。
- 获取方式：RSS、网页、API、手动录入、Newsletter、YouTube 链接、播客、访谈/视频转录等。
- 可靠性备注。
- 该来源主要产出事实、观点，还是两者都有。

第一版不应做成庞大的自动化系统。一个小型、可编辑的 JSON 文件或 SQLite 表就足够。

### 第三层：手动录入高价值材料

很多高价值观点来自访谈、播客、演讲、财报电话会、社交平台帖子或视频，它们不一定适合 RSS。

V4 应支持手动录入：

- 来源 URL。
- 发言人或机构。
- 日期。
- 主题。
- 原始引文或摘录。
- 用户备注。
- AI 提取出的观点卡片。

手动录入很重要，因为真正有价值的产业判断经常出现在不规整的信息渠道里。

### 第四层：后续集成

不要一开始就对所有平台做广泛自动化。应等观点卡片闭环跑通后，再考虑更多集成。

后续可考虑的来源包括：

- YouTube 转录文本。
- 播客转录文本。
- SEC 文件和财报电话会文本。
- arXiv 和论文订阅源。
- GitHub 仓库和 release notes。
- X、LinkedIn 或其他社交平台，但前提是访问方式和信号质量值得引入额外复杂度。

## 观点卡片字段

早期观点卡片应尽量记录：

- 来源文档 ID 或 URL。
- 发言人或机构。
- 相关组织。
- 所属产业方向。
- 主题。
- 核心判断。
- 推理过程。
- 证据。
- 预测，如果有。
- 时间范围，如果有。
- 分析维度：技术、工程、市场、资本、政策、供应链、组织能力或用户需求。
- 立场：看多、怀疑、中性、不确定、预警或探索。
- 可信度。
- 验证状态：未验证、已支持、部分支持、已证伪或已过期。
- 用户备注。
- 创建和更新时间。

## 第一阶段实现建议

V4 第一阶段不应同时解决采集、产业建模、自动提取、因果分析和验证所有问题。

更新后的推荐顺序：

1. 继续维护最小信息源注册表，覆盖 V4 产业方向、企业、人物和观点来源。
2. 如果当前数据库仍依赖手工改表，先加入数据库迁移机制。
3. 建立产业、细分赛道、企业/机构、人物和关键事件的最小数据模型。
4. 建立事件与参与者、赛道、来源和原始文档之间的关联。
5. 支持人工创建、编辑、合并和确认事件，并从现有文章生成待确认事件候选。
6. 新增事件台账、参与者时间线和事件详情页。
7. 在事件档案中加入可核查主张和观点卡片，保留原始来源、用户备注和验证状态。
8. 建立一个试点赛道的动态产业档案浏览路径。

更新后的 V4 核心闭环是：

```text
产业/赛道 -> 参与者 -> 关键事件 -> 来源与文档
          -> 可核查主张/观点 -> 人工确认 -> 动态产业档案
```
