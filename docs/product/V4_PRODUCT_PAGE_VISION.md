# OrbitAI V4 用户页面长期方向

类别：产品方向

状态：用户已于 2026-07-16 明确确认页面总体方向，并于 2026-07-18 决定提前建立新的阅读端模板骨架；具体视觉稿和控件细节继续随试点迭代。

## 1. 当前页面与最终页面不是同一定位

早期 `/industries/artificial-intelligence` 页面沿用了 OrbitAI 原有的 Jinja2 模板和 CSS，主要用途是验证以下技术链路：

```text
数据库 -> 仓储 -> 服务 -> 路由 -> 模板 -> 浏览器
```

该工程预览页已经完成使命。2026-07-18 起，产业档案改用独立的 `templates/dossier/` 和 `static/dossier/` 阅读端骨架；三个一级入口和页面下钻关系从现在开始保持稳定，视觉细节仍可在试点过程中迭代。RSS 材料页与管理页继续保留自己的模板和 CSS，避免相互影响。

## 2. 最终首页的三个一级选项

V4 面向用户的主要入口上方设置三个一级选项：

1. 产业结构
2. 企业档案
3. 人物档案

默认打开“产业结构”。其他顶层产业在很久以后才会建设，因此当前不需要为了多产业切换设计复杂的首页层级。

## 3. “产业结构”默认展示什么

用户进入后应直接看到 AI 产业整体结构，而不是先看到信息流、统计卡片或普通目录列表。

结构图需要完整呈现：

```text
AI 产业结构
-> 核心能力
-> 基础设施
-> 产品与应用
-> 外部环境
-> 四大分组下的 26 个赛道
```

整体体验可以接近思维导图或产业结构图：产业位于中心或主轴，四大分组形成正式层级，各赛道从分组展开。四大分组之间的支持、依赖、供应、采用等关系属于后续产业分析内容，本阶段暂不加入。

## 4. 点击赛道后的页面

点击“通用基础模型（含大语言模型）”后跳转到独立赛道页面，而不是只在产业总览页展开一段摘要。

赛道页分为两层：

### 4.1 页面上部：赛道介绍与总体发展历程

- 解释赛道定义、边界和主要研究对象。
- 展示赛道的大致发展阶段和重要变化。
- 总体发展历程可以从各企业的模型与产品发展时间线中提取共性，再形成赛道层总结。
- 共性总结必须能够追溯到企业事件和原始材料，并标明时间范围、不确定性或仍待补证据之处；AI 归纳不能直接冒充已确认事实。

### 4.2 页面下部：各企业的发展时间线

- 分别展示 OpenAI、Anthropic、Google DeepMind、Meta AI、DeepSeek、SpaceXAI 等试点组织的发展时间线。
- V4.1 可以先显示参与者骨架；V4.2 处理好事件后，把已确认事件挂到对应企业时间线上。
- 点击时间线中的事件，进入独立事件档案。

## 5. 事件档案的下钻方向

完整浏览路径为：

```text
产业结构
-> 赛道页面
-> 企业发展时间线
-> 关键事件
-> 事件档案
-> 原始来源、文档、主张、观点与验证状态
```

事件档案不是新闻文章的复制品。多篇材料报道同一事件时，应汇入同一个事件档案，并继续保留不同来源、冲突和不确定性。

## 6. 企业档案和人物档案

“企业档案”和“人物档案”从首页一级选项直接进入。它们最终应与赛道页和事件档案互相连接，但具体列表、检索、筛选及详情布局，等相应页面开始开发时再单独确认，不在当前阶段提前定死。

## 7. 当前阶段明确不做

- 不把当前骨架误称为最终视觉定稿。
- 不为了视觉完整而提前制作没有事件和来源支撑的时间线内容。
- 不提前制作四大产业分组之间的复杂关系图。
- 不提前建设其他顶层产业或复杂的多产业切换。
- 不把无来源的 AI 综合文字当作赛道发展史。
