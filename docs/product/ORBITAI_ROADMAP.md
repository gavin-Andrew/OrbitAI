# OrbitAI 产品与技术路线图

类别：产品方向

状态：用户已审核确认，自 2026-07-10 起作为 OrbitAI 的正式总体路线图。

版本：2026-07-15

这份路线图描述 OrbitAI 从当前 AI 信息雷达出发，经过“可追溯的 AI 动态产业档案”、目的驱动的产业分析、持续验证和个人判断沉淀，最终成长为可迁移到其他产业的个人产业认知系统的总体路径。

路线图中的版本名称用于表达能力依赖，不是发布日期承诺。每一阶段只有在达到退出标准后，才进入下一阶段；具体数据表、页面和 AI 工作流仍应在各阶段开始前另写实现规格。

## 1. 为什么重新制定路线图

OrbitAI 已经具备 RSS 抓取、AI 摘要与分类、SQLite 历史存储、FastAPI 本地服务、页面浏览和状态监控等基础能力。旧静态快照链路已在结构重构阶段 5 退役；此前的 V4 方向进一步提出了信息源注册表、事实材料和观点卡片。

这些工作仍然有效，但只解决了“材料从哪里来”和“材料中有什么”，还没有形成一条能够介绍产业、解释事件和支持长期判断的主线。

新的核心认识是：

- 文章是原始材料，不是最终知识单元。
- 观点是对现实的判断和解释，不是产业历史本身。
- 事件把产业、企业、人物、来源、事实、观点和时间连接起来。
- 企业与人物时间线让产业发展变得可理解、可叙述。
- 数据库和分析框架不会自动产生唯一的产业分析；分析必须服务于明确目的和研究问题。

因此，V4 的主线从“观点源与观点卡片”调整为“可追溯的 AI 动态产业档案”。观点卡片和信息源注册表不被废弃，而是成为事件档案和后续分析中的材料层。

## 2. 北极星目标

OrbitAI 的长期定位是：

> 一个以产业事件为核心，以企业与人物时间线为叙事入口，以多源事实、主张、观点和证据为材料，以影响因素与因果链为分析语言，并通过持续跟踪和验证帮助用户形成自身判断的本地优先产业研究系统。

OrbitAI 不追求自动生成一个看似完整、实际不可追溯的“最终答案”。它要提供一个研究环境，让用户能够：

- 把一个产业讲清楚。
- 追溯某个结论来自哪些材料。
- 理解企业和人物如何推动产业演化。
- 围绕具体问题选择适合的分析方法。
- 保存假设、分歧、不确定性和反证。
- 用后续现实检验过去的观点和分析。
- 长期沉淀自己的产业判断方式。

一句更简洁的产品表达是：

> OrbitAI 首先把产业讲清楚，然后围绕具体问题分析产业，最后在长期验证中帮助用户形成自己的判断体系。

## 3. OrbitAI 的核心公式

产业数据库与分析框架是分析的基石，但不是分析结果本身。

```text
研究目的
+ 具体问题
+ 研究对象、范围与时间尺度
+ 可追溯的产业数据库
+ 与问题匹配的分析框架
= 一次有边界、可复查、可更新的产业分析
```

其中：

- 数据库回答“我们知道什么、谁这样说、证据在哪里”。
- 分析框架回答“应该观察哪些变量，以及怎样解释它们的作用”。
- 研究目的回答“这次为什么分析、要支持什么认识或行动”。
- 分析产物回答“在当前证据和假设下，我们暂时得到什么结论”。
- 验证机制回答“后来发生的现实是否支持这份结论”。

由此，OrbitAI 不建设一套包打天下的固定分析模板，而是建设“共同分析语法 + 目的化分析模板”。

共同分析语法是：

```text
参与者 -> 背景条件 -> 触发事件 -> 影响因素 -> 作用机制
        -> 一阶结果 -> 二阶影响 -> 反馈 -> 后续验证
```

目的化模板包括产业介绍、事件影响分析、企业战略分析、竞争比较、趋势判断、情景推演和决策支持等。

## 4. 五层产品结构

### 4.1 原始材料与证据层

负责保存和追溯公开材料：

- 官网公告、产品文档、论文、政策文件和监管文件。
- 新闻报道、采访、播客、演讲、财报和电话会。
- 用户反馈、开发者反馈、基准测试、价格和交付数据。
- 用户手动录入的摘录、备注和待调查线索。

这一层必须保留原始 URL、来源身份、发布时间、获取时间、原文片段、材料类型和处理状态。AI 提取出的任何内容都不能脱离原始材料存在。

### 4.2 产业世界模型层

负责描述“产业由什么构成、谁在其中、发生过什么”：

- 产业和细分赛道。
- 支撑层、供应关系、依赖关系和竞争关系。
- 企业、机构、人物、研究组织、政策部门和社区。
- 关键事件及其参与者。
- 企业发展时间线、人物身份变化和观点演变。

这里的“世界模型”首先是清晰的关系型数据模型，不代表 V4 需要图数据库或复杂知识图谱。

### 4.3 分析框架层

负责描述“怎样理解事件和产业变化”：

- 技术、科学、工程、产品、市场、用户需求。
- 资本、成本、商业模式和宏观经济。
- 芯片、算力、能源、供应链和制造。
- 政策、监管、标准和地缘政治。
- 人才、组织能力、企业战略和竞争格局。
- 因素之间的作用机制、反馈关系和关键约束。

影响强度与判断置信度必须分开保存。早期优先使用“弱、中、强”和清晰机制说明，不急于生成缺乏依据的精确百分比权重。

### 4.4 研究任务层

每次正式分析都应先定义：

- 分析目的。
- 核心问题。
- 研究对象和产业范围。
- 起止时间与判断时间尺度。
- 目标读者或使用场景。
- 已知前提、关键假设和不做什么。
- 需要采用的分析模板。

同一批数据库材料可以服务于不同研究任务，因此研究任务必须独立保存，不能把某次分析结论写回成永恒事实。

### 4.5 产物、验证与个人认知层

负责形成和长期维护：

- 动态产业档案。
- 企业与人物发展档案。
- 事件分析、企业分析和比较分析。
- 趋势判断、情景推演和待验证假设。
- 用户自己的备注、结论、异议和判断日志。
- 预测、观察信号、验证结果和分析版本。
- 人物或机构的长期观点轨迹与判断框架画像。

最终价值不只是积累更多内容，而是让用户能够看到自己的认识怎样形成、为何改变、哪些判断经受住了现实检验。

## 5. AI 产业的组织方式

AI、LLM、智能体、具身智能、芯片、算力和能源不处在同一个分类层级，不能只用一棵父子分类树表达。

第一版目录采用四个相互关联的部分。

### 5.1 核心能力

- 通用基础模型。
- 多模态理解与生成。
- 推理与规划。
- 智能体核心能力。
- 世界模型与物理智能。

### 5.2 基础设施

- 数据。
- AI 芯片。
- 先进制程、封装和半导体设备。
- 云计算和算力平台。
- 网络和数据中心。
- 电力、能源和冷却。

### 5.3 产品与应用

- AI Agent 与软件自动化。
- AI 编程和生产力工具。
- AI 搜索、助手和内容产品。
- AI 终端和智能硬件。
- 具身智能与机器人。
- 自动驾驶。
- 医疗、教育、金融、制造等行业应用。
- 科学 AI。

### 5.4 外部环境

- 政策与监管。
- 安全治理和标准。
- 资本和融资。
- 人才。
- 开源社区。
- 客户、开发者和用户采用。
- 国际贸易与供应限制。

产业与赛道之间除了“属于”，还应允许表达“支持、依赖、供应、采用、竞争、替代、合作、监管和影响”等关系。V4 可先用少量受控关系类型和普通关联表实现。

## 6. 核心概念数据对象

以下是长期概念模型，不意味着第一版必须一次建立所有数据表。

| 对象 | 作用 | 关键要求 |
|---|---|---|
| Industry | 表示 AI、金融等大类产业 | 有边界、说明和版本 |
| Segment | 表示基础模型、智能体、芯片等细分方向 | 允许跨产业和相互关系 |
| Organization | 公司、实验室、政府部门、社区等 | 保存别名、类型和存续状态 |
| Person | 关键人物 | 身份和机构关系必须带时间 |
| Event | 产业历史中的关键发生 | 允许多参与者、多赛道和日期精度 |
| Source | 长期追踪的信息源身份 | 与具体获取入口分开 |
| Document | 公告、文章、论文、视频转录等原始材料 | 必须保留原文和来源 |
| Claim | 某个材料提出的可核查陈述 | 可被支持、反驳或保持争议 |
| Viewpoint | 人物或机构的判断、解释和预测 | 保存归属、语境、时间和原文 |
| EvidenceLink | 材料、主张、事件与分析之间的证据关系 | 标明支持、反驳或仅作背景 |
| FactorAssessment | 某因素在特定事件或问题中的作用判断 | 保存方向、强度、机制、置信度和时间尺度 |
| CausalLink | 两个因素、事件或结果之间的因果假设 | 必须区分观察与推断 |
| ResearchTask | 一次研究的目的、问题和边界 | 决定采用什么框架 |
| Analysis | 基于某一时点证据形成的分析版本 | 不覆盖历史版本 |
| Signal | 未来需要持续观察的指标或事件 | 有触发条件和来源 |
| Validation | 对观点、预测、因果假设或分析的后续验证 | 支持、部分支持、反驳、过期或未决 |

事件的“客观内核”和来源对事件的描述需要分开。官网通常是证明“公司宣布或发布了什么”的一手来源，但不能独自证明采用效果、竞争优势或长期影响。重要事件应允许同时保存官方来源、独立报道、专家解释和用户反馈。

## 7. 最终产品形态

### 7.1 产业档案

回答“这个产业是什么、由谁构成、如何发展至今”：

- 产业边界和结构图。
- 细分赛道与支撑关系。
- 关键企业、机构与人物。
- 关键事件时间线。
- 当前阶段、主要共识、争议和待观察信号。

### 7.2 企业与人物档案

- 企业历史、产品路线、组织变化和关键决策。
- 企业参与的事件及其在不同赛道中的位置。
- 人物身份变化、观点演变、预测和后续验证。
- 原始材料和相关事件的双向追溯。

### 7.3 事件档案

- 事件发生了什么以及时间精度。
- 参与者、相关赛道和事件类型。
- 官方来源、独立来源和材料间的差异。
- 可核查主张、关键数据、人物观点和用户反馈。
- 已观察影响、待验证影响和争议点。

### 7.4 分析工作台

- 创建研究目的和问题。
- 选择事件、企业、时间范围和材料。
- 评估影响因素、关键约束和相互作用。
- 组织因果链、反事实、分歧和置信度。
- 生成可编辑、可引用、可版本化的分析草稿。

### 7.5 跟踪与验证中心

- 保存预测、假设和待观察信号。
- 在新事件发生时提示可能需要复查的旧结论。
- 记录支持、部分支持、反驳和仍未验证的结果。
- 展示观点、人物和分析框架的长期准确性与适用边界。

### 7.6 个人研究空间

- 用户笔记、问题列表、阅读线索和分析草稿。
- 用户对 AI 建议的接受、修改和拒绝记录。
- 用户自己的判断日志和框架演化。
- 根据正在研究的问题生成下一步材料和验证建议。

## 8. 总体版本路线

| 阶段 | 核心目标 | 主要交付物 | 退出标准 |
|---|---|---|---|
| V3：信息雷达 | 收集、摘要和浏览 AI 信息 | RSS、文章库、摘要、分类、状态页、快照 | 当前基础能力稳定可用 |
| V4：动态产业档案 | 把材料组织成可追溯的产业、企业和事件历史 | 产业结构、参与者档案、事件台账、时间线、事件档案 | 能从产业逐层追溯到企业、事件和原始来源 |
| V5：目的驱动分析 | 围绕明确问题分析事件与企业 | 研究任务、因素评估、因果链、分析版本 | 能完成一份证据可追溯的事件或企业分析 |
| V6：比较与框架沉淀 | 跨企业、跨事件发现模式与分歧 | 比较分析、产业阶段、关键约束、框架库 | 框架能在多个案例中复用并说明边界 |
| V7：持续验证 | 让观点、预测和分析接受现实检验 | 信号跟踪、验证记录、结论复查、置信度变化 | 新事件能触发旧判断复查并保留历史 |
| V8：个人认知系统 | 沉淀用户自己的研究与判断方式 | 个人判断日志、研究队列、框架演化、辅助复盘 | 系统能说明用户的结论怎样形成和改变 |
| V9：人物画像与有限蒸馏 | 提炼人物和机构的长期判断框架 | 观点轨迹、预测记录、判断风格画像、可追溯研究助手 | 画像有足够样本、来源和验证，且不冒充本人 |
| V10：跨产业扩展 | 把共同能力迁移到金融等其他产业 | 通用核心、领域包、领域特定框架和数据源 | 新产业无需重写核心系统即可建立档案与分析 |

## 9. V4：可追溯的 AI 动态产业档案

### 9.1 V4 的目标

V4 首先解决“怎样把 AI 产业讲清楚”，而不是立即自动完成完整产业分析。

V4 的核心浏览路径是：

```text
AI 产业
-> 细分赛道与支撑关系
-> 关键企业、机构和人物
-> 企业或人物发展时间线
-> 关键事件档案
-> 原始来源、事实主张、观点和反馈
```

V4 全阶段采用单赛道纵向试点。第一个且当前唯一的深度试点正式确定为“通用基础模型（含大语言模型）”：从 V4.1 到 V4.5，产业与参与者目录、事件台账与时间线、事件档案与证据、动态产业档案以及整理工作流与质量闭环都先在这一赛道依次跑通。只有该试点达到 V4 退出标准后，才横向补充其他赛道的参与者、事件、来源证据和档案内容。

这一约束限制的是当前内容范围，不是系统能力范围。已经确认的 AI 产业目录骨架可以保留，未建设赛道应明确显示为空白或待建设；数据库、仓储、路由和页面必须继续保持赛道通用，不能把“通用基础模型”硬编码成唯一业务对象。

### 9.2 V4 的建议子阶段

#### V4.0：范围和数据模型

- 确认 AI 产业第一版边界、细分赛道和关系类型。
- 确认“通用基础模型（含大语言模型）”为 V4 全阶段唯一的深度试点赛道。
- 定义事件粒度、事件类型、状态和日期精度。
- 定义来源、文档、主张、观点和事件之间的关系。
- 引入简单、可回滚的 SQLite 数据库迁移机制。

#### V4.1：产业与参与者目录

- 建立产业、赛道、企业、机构和人物的基础表。
- 参与者、人物、别名、任职和来源映射内容只建设“通用基础模型（含大语言模型）”试点；其他赛道暂时只保留目录骨架或待建设状态。
- 将现有 `data/registries/sources.v4.json` 映射到企业和人物身份。
- 支持企业别名、人物任职时间和跨赛道关系。
- 提供产业、赛道和参与者的最小浏览页与编辑入口。

#### V4.2：事件台账与时间线

- 建立事件、事件参与者、事件赛道和事件来源关系。
- 支持人工创建、编辑、合并和标记候选事件。
- 从现有文章生成“事件候选”，但必须经过用户确认。
- 提供企业、人物和赛道时间线。

#### V4.3：事件档案与证据

- 为事件绑定多个来源和原始文档。
- 区分官方来源、独立来源、专家观点和用户反馈。
- 保存可核查主张、证据片段、冲突和验证状态。
- 将原“观点卡片”能力作为事件档案中的观点层实现。

#### V4.4：动态产业档案

- 建立 AI 产业总览和试点赛道详情页。
- 展示产业结构、关键参与者、关键事件和历史阶段。
- 支持从产业介绍逐层下钻到来源。
- 显示尚未覆盖的空白、争议和待补证据，而不是用 AI 文案填满页面。

#### V4.5：整理工作流与质量闭环

- 建立候选、已确认、有争议、待补证据和已归档状态。
- 支持用户修改 AI 提取结果，并保留修改痕迹。
- 建立最小的数据完整性检查和测试。
- 让新增材料能够关联已有事件，或形成待确认的新事件。

### 9.3 V4 退出标准

进入 V5 前，至少应满足：

- 用户能从 AI 产业页进入一个深度赛道，再进入关键企业和事件。
- 一个试点赛道已经形成可阅读的关键企业与事件时间线。
- 每个已确认事件至少有一个可追溯来源，关键事件允许多个相互独立的来源。
- 事件、来源、主张和观点在数据上可以区分。
- 一个事件可以关联多个参与者和赛道。
- AI 生成字段有明确标记，用户能够修改和确认。
- 信息源注册表、现有文章库和事件档案已经连通。
- 页面能够明确展示未知、争议和证据不足。

### 9.4 V4 明确不做

- 不建立完整因果分析引擎。
- 不自动计算影响因素的精确权重。
- 不自动生成确定性的产业预测或投资建议。
- 不覆盖全部 AI 子产业、公司和社交媒体。
- 不建设图数据库或复杂知识图谱。
- 不进行人物人格模拟或模型蒸馏。
- 不用大规模自动采集代替人工策划和事件确认。

## 10. V5：目的驱动的分析工作台

V5 开始把产业数据库转化为针对具体问题的分析能力。

主要建设内容：

- `ResearchTask`：保存目的、问题、对象、范围、时间尺度、读者和假设。
- 分析模板：产业介绍、事件影响、企业战略和企业比较优先。
- `FactorAssessment`：保存因素方向、强度、机制、置信度、时间范围和证据。
- `CausalLink`：连接背景条件、事件、机制、结果和反馈。
- 分歧分析：比较不同来源、人物和时间尺度下的解释。
- 分析版本：用户或 AI 修改结论时不覆盖旧版本。
- 分析引用：每个关键判断都能回到事件、主张和原始材料。

V5 的退出标准不是“AI 能写一篇长报告”，而是用户能够围绕一个明确问题，完成一份结构化、可编辑、证据可追溯且标明不确定性的分析。

## 11. V6：比较分析与框架沉淀

当事件分析积累到一定数量后，OrbitAI 才开始从案例中归纳可复用框架。

主要建设内容：

- 企业时间线、战略选择和资源条件比较。
- 同类事件的横向比较和历史阶段比较。
- 产业发展阶段、关键约束和转折信号识别。
- 共识、分歧及其来源分析。
- 框架库：适用对象、变量、机制、案例、反例和失效条件。
- 跨赛道依赖分析，例如模型需求怎样传导至芯片、算力和能源。

框架不是静态教科书章节，而是从多个事件中抽象出来、能够在新案例中被再次检验的分析工具。

## 12. V7：持续跟踪与验证闭环

V7 让系统从“保存过去”进入“用现实检验过去”。

主要建设内容：

- 将观点中的预测、分析中的假设和关键变量转化为待观察信号。
- 为信号定义时间范围、触发条件、来源和复查日期。
- 新事件进入时，提示可能相关的旧观点和旧分析。
- 保存支持、部分支持、反驳、过期和仍未决的验证结果。
- 展示结论置信度为何提高或降低。
- 复盘哪些框架在哪些产业阶段有效，在哪些情况下失效。

验证不是给人物或模型制作简单胜率排行榜，而是理解判断成立所依赖的条件。

## 13. V8：个人产业认知系统

V8 的中心从“产业发生了什么”进一步转向“用户如何形成判断”。

主要建设内容：

- 个人研究问题、阅读队列、调查线索和周期性复盘。
- 用户判断日志及其引用的证据、框架和假设。
- 记录用户接受、修改或拒绝 AI 建议的原因。
- 识别长期关注主题、重复使用的框架和可能忽略的变量。
- 在新证据出现时提示用户复查相关旧判断。
- 形成用户自己的产业分析模板和研究习惯。

AI 在这一阶段仍是研究协作者，不是替用户作出最终判断的权威。

## 14. V9：人物判断画像与有限蒸馏

长期积累足够多的原始观点、语境、时间线、预测和验证结果后，OrbitAI 可以提炼人物或机构的判断框架。

优先产物应是：

- 长期观点轨迹。
- 对关键变量的关注变化。
- 常用推理路径和时间尺度。
- 预测及其成立条件与验证记录。
- 观点与其所在组织、利益位置和产业阶段的关系。

只有在数据量、授权、质量和评测条件都满足时，才考虑检索增强、微调或其他形式的“蒸馏”。目标应是构建可追溯的判断框架助手，而不是声称复制或冒充马斯克、黄仁勋等真实人物。

## 15. V10：扩展到金融等其他产业

跨产业扩展时，应把系统拆成两部分：

- 通用核心：来源、文档、参与者、事件、主张、证据、研究任务、分析、信号和验证。
- 领域包：产业分类、事件类型、指标体系、专用来源和领域分析框架。

金融、能源、航天、生物科技或制造业可以复用通用核心，但不能直接照搬 AI 产业的变量和因果框架。涉及金融、医疗、法律等高风险领域时，还需要更严格的数据质量、合规和决策边界。

## 16. 技术演进路线

### V4 技术原则

- 继续使用 FastAPI、Jinja2 和 SQLite。
- 先建立数据库迁移机制，再增加多张核心表。
- 保持仓储层封装，避免路由直接散落 SQL。
- 优先服务端渲染和简单交互，不为展示效果引入重型前端框架。
- 为迁移、核心仓储方法、关键路由和事件关联补最小测试。
- 动态研究工作流以本地 Web App 为主。若未来需要公开只读发布，应另写实现规格建立独立导出流程，不恢复已经退役的旧静态快照链路。

### 后续升级触发条件

- SQLite 只有在多人协作、远程部署、高并发写入或数据规模明确造成瓶颈时才考虑替换。
- 全文搜索优先评估 SQLite FTS；向量检索只在语义检索有明确收益和评测后引入。
- 图数据库只有在关系查询成为真实瓶颈、普通关联表无法维护时再评估。
- 自动采集范围只有在手动闭环证明某类材料持续有价值后扩大。
- AI 模型和提示词必须可替换，业务数据结构不能依赖某个单一模型输出格式。

## 17. 数据质量与认识论规则

- 事件存在客观内核，但事件边界、命名、日期和影响可能存在争议。
- 来源证明“谁在何时说了什么”；来源权威性不自动等于主张真实。
- 第一方来源、独立来源、专家观点和用户反馈承担不同证据角色。
- 事实、主张、观点、推断、预测和验证结果必须能够区分。
- 影响强度、证据质量和判断置信度不能合并成一个分数。
- AI 提取、AI 推断、用户确认和用户判断必须有不同标记。
- 分析必须带研究目的、时间点、范围、假设和版本。
- 保存矛盾和未知，不强行生成单一共识。
- 用户可以修正、合并、拆分和撤回错误事件或主张，并保留必要历史。

## 18. 衡量成功的方式

OrbitAI 不以抓取文章数量、AI 生成字数或页面数量作为主要成功指标。更重要的是：

- 可追溯率：重要事件和分析判断有多少能够回到原始来源。
- 结构完整度：产业、参与者、事件和来源之间是否形成有效连接。
- 人工修正率：AI 结果是否容易被发现、修改和确认。
- 检索复用率：过去材料能否在新研究问题中被重新使用。
- 分歧保留度：系统是否保存了相互冲突的证据和观点。
- 验证闭环率：预测、假设和待观察信号是否得到后续复查。
- 认知增益：用户是否更容易解释产业、提出问题和发现关键变量。

## 19. 当前已明确与仍待确认的事项

### 已明确的方向

- OrbitAI 是本地优先的个人产业研究系统。
- 当前先聚焦 AI 与相关硬科技产业。
- V4 名称和主线是“可追溯的 AI 动态产业档案”。
- V4 第一个且当前唯一的深度试点是“通用基础模型（含大语言模型）”。
- V4.1 至 V4.5 先在该赛道跑通完整闭环并达到 V4 退出标准，再横向补充其他赛道内容；实现本身必须保持赛道通用。
- V4.1 首批名册范围已经确认采用 6 个组织和 6 位人物，具体名单与仍待复核的数据边界见 `docs/specs/V4_1_CATALOG_SPEC.md`。
- V4.1 首个页面已经确认采用产业/赛道总览，并完整保留核心能力、基础设施、产品与应用、外部环境四大目录分组；不能把 26 个赛道渲染成无分组列表。
- 事件是串联产业、企业、人物、来源、事实和观点的核心对象。
- 企业历史和人物观点演变是重要的产业叙事入口。
- 信息源注册表和观点卡片继续保留，但成为事件档案的材料层。
- 产业分析必须由目的和具体问题驱动。
- 分析结论需要版本化、可追溯并接受后续验证。

### 后续开发仍需确认

- 第一批关键事件的策划范围。
- 事件粒度和“关键事件”的人工选择标准。
- 旧文章库中哪些内容值得回填为事件，哪些只作为普通材料保留。

## 20. 当前 V4.1 开发起点

V4.0 已经完成第一版范围、对象关系和迁移基线。下一开发切片从 V4.1 的试点名册开始：

1. 新建 V4.1 实现规格，明确“内容单赛道、能力保持通用”的范围和退出标准。
2. 确认“通用基础模型（含大语言模型）”第一批核心组织、人物和来源。
3. 建立产业、赛道、参与者和来源的仓储、导入预览与冲突报告。
4. 提供最小浏览和人工纠错入口，验证别名、任职时间、跨赛道关系和来源身份映射。
5. 准备一小组后续验证材料；文章到事件候选的处理留到 V4.2。

V4 后续开发不从横向铺开目录或大规模抓取开始，而从一条可以人工验证的纵向路径继续推进：

```text
一个试点赛道
-> 少量关键企业
-> 一组关键事件
-> 多个原始来源
-> 可核查主张与人物观点
-> 可浏览、可编辑、可追溯的动态产业档案
```
