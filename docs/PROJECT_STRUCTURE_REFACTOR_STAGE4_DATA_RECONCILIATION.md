## 3. 字段级对账

对 56 条匹配记录逐一比较 18 个逻辑字段，共比较 1008 个字段值。标签同时兼容 JSON 列表、SQLite JSON 文本和旧 `||` 分隔格式后再比较。

链接作为 56 条记录的匹配键，全部一一对应；它不计入下述 18 类对比字段。

以下 16 类字段在 56 条记录中全部一致：

- 标题、来源、发布时间、抓取时间、原始摘要、规则分类。
- AI 中文标题、AI 摘要、AI 分类、标签、综合分、处理状态。
- AI 错误、错误类型、失败时间和重试次数。

发现两类稳定差异：

| 字段 | 差异记录 | 解释 |
| --- | ---: | --- |
| `ai.scores` | 56 | 旧 JSON 保留五项逐维评分；SQLite 的 `scores` 为空或默认值，但 56 条 `final_score` 全部一致。 |
| `ai.processed_at` | 56 | 旧 JSON 保留 AI 处理时间；SQLite 对应值为空，但处理状态与综合分全部一致。 |

SQLite 中的标签使用旧 `||` 分隔格式；经过仓储层现有兼容解析后，56 条标签全部与 JSON 一致，不属于语义差异。

## 4. 处置结论

- `var/orbitai.db` 作为活动主数据库，因为它覆盖旧 JSON 的全部 56 个链接，并额外包含 100 条文章及完整 V4 目录数据。
- `data/archive/data.json` 不能删除，因为它仍独立保留逐维评分和 AI 处理时间。
- 旧 JSON 不再参与活动读写，只作为 Git 忽略的历史归档保留。
- 阶段 5 的清退确认不得被解释为自动授权删除该归档；是否删除必须基于这份差异记录再次单独判断。
