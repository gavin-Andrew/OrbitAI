# OrbitAI V4.1-C 首个产业目录页面开发说明

类别：操作与实现指南

状态：首个产业目录工程验证页已经实现；它用于跑通数据与浏览链路，不代表最终面向用户的页面设计。V4.1-C 的独立赛道、组织、人物详情页和来源映射页仍待后续开发。

版本：2026-07-16

## 0. 这张页面的阶段定位

当前页面复用了 OrbitAI 既有的 Jinja2 基础模板和 CSS，以卡片目录形式验证“数据库 -> 仓储 -> 服务 -> 路由 -> 页面”的技术链路。它可以继续用于通用基础模型试点开发，但不应被当作最终用户界面的设计基准。

最终页面将以可视化的 AI 产业结构作为默认入口，上方设置“产业结构、企业档案、人物档案”三个一级选项，并沿“产业结构 -> 赛道页 -> 企业发展时间线 -> 事件档案”逐层浏览。完整方向见 `docs/product/V4_PRODUCT_PAGE_VISION.md`。试点闭环完成前暂不大规模重写当前模板和样式。

2. 把审核通过的“人工智能产业、四大分组、26 个赛道、6 个组织、6 位人物”安全写入 `var/orbitai.db`。

这时数据虽然已经存在，但普通用户看不见它。可以把数据库想成仓库：货物已经入库，货架也已经整理好，但还没有商店页面让人浏览。

## 2. 这一轮要得到什么

首个页面需要把数据库中的产业目录变成浏览器可以阅读的网页：

```text
人工智能产业
-> 核心能力（5 个赛道）
-> 基础设施（6 个赛道）
-> 产品与应用（8 个赛道）
-> 外部环境（7 个赛道）
```

四大分组和 26 个赛道必须全部显示。当前已经有参与者名册的赛道高亮，其余赛道显示“待建设”，不能用生成内容填满空白。

## 3. 一次网页访问是怎样流动的

```text
用户打开网址
    |
    v
FastAPI 路由：判断用户想看哪个产业
    |
    v
目录服务：组织四大分组并计算页面状态
    |
    v
仓储层：向 SQLite 查询产业、赛道、组织和人物
    |
    v
Jinja2 模板：把数据填进 HTML 页面骨架
    |
    v
CSS：决定颜色、间距、卡片和手机端布局
    |
    v
浏览器显示完整页面
```

这五层各管一件事，因此以后更换页面外观，不需要重写数据库查询；以后增加新产业，也不需要复制一套新路由。

## 4. 这次具体做了什么

### 4.1 仓储层：从数据库取货

文件：`orbitai/catalog/repository.py`

新增的读取方法负责：

- 按 `slug` 查找产业。
- 读取产业下的全部赛道。
- 统计每个赛道关联了多少组织和人物。
- 读取已建设赛道的组织和人物摘要。

“仓储层”不是保存文件的文件夹，而是一组集中访问数据库的代码。这样页面不需要到处编写 SQL，数据读取规则更容易测试和维护。

### 4.2 目录服务：把原料整理成页面数据

文件：`orbitai/catalog/service.py`

数据库保存了每个赛道的 `segment_kind`，目录服务根据它把赛道装进固定顺序的四大分组。

当前数据库没有单独保存 `pilot_active` 或 `directory_only`。本轮不新增迁移，而是采用可验证的规则：

```text
组织数量 + 人物数量 > 0  -> 已建设
组织数量 + 人物数量 = 0  -> 待建设
```

因此页面没有写死“通用基础模型一定是试点”。如果以后把参与者关联到另一个赛道，页面会根据真实关系自动改变高亮对象。

四大分组的中文名称、解释和显示顺序属于页面展示规则，暂时放在目录服务的配置中；赛道归属仍以数据库为准。

### 4.3 路由：网址的接待员

文件：`app.py`

新增网址：

```text
/industries/{industry_slug}
```

当前人工智能产业页面是：

```text
http://127.0.0.1:8000/industries/artificial-intelligence
```

`slug` 是适合放进网址的稳定英文标识。例如中文名称是“人工智能产业”，对应的 slug 是 `artificial-intelligence`。如果 slug 不存在，路由返回 404，表示没有找到该页面。

路由本身不负责写 HTML，也不直接编写 SQL。它只接收请求、调用目录服务、把结果交给模板。

### 4.4 模板：网页骨架

文件：`templates/industry_catalog.html`

Jinja2 模板是“带占位符的 HTML”。例如 `{{ catalog.segment_count }}` 在浏览器收到页面前，会被替换成真实数字 `26`。

模板现在展示：

- 4 大目录分组、26 个赛道、已建设和待建设数量。
- 四大分组的说明和全部赛道卡片。
- 当前试点的 6 个组织和 6 位人物摘要。
- 明确的单赛道建设边界。

`templates/base.html` 增加了可替换的统计区块，并在公共导航中增加“产业目录”。这叫“模板继承”：多个页面共用头部、导航和页脚，目录页只替换自己不同的部分。

### 4.5 CSS：页面外观

文件：`static/style.css`

CSS 不决定数据是什么，只决定数据怎样显示。本轮新增了：

- 四大分组卡片和不同的顶部识别色。
- 已建设试点与待建设赛道的视觉区分。
- 组织和人物双栏名册摘要。
- 手机窄屏时自动改成单栏的响应式布局。

### 4.6 测试：自动检查作业

文件：`tests/catalog/test_catalog_page.py`

测试会自动检查：

- 四大分组顺序是否正确。
- 分组数量是否仍为 5、6、8、7，总数是否为 26。
- 当前是否为 1 个已建设、25 个待建设。
- 把参与者临时换到另一个赛道后，高亮是否会跟着数据变化。
- 页面是否真的渲染四大类、试点名册和“待建设”。
- 不存在的产业是否返回 404。

测试使用临时数据库，不会修改正式的 `var/orbitai.db`。

## 5. 怎样在本地查看

在项目目录运行：

```powershell
uvicorn app:app --reload
```

然后在浏览器打开：

```text
http://127.0.0.1:8000/industries/artificial-intelligence
```

停止服务时，在终端按 `Ctrl+C`。
