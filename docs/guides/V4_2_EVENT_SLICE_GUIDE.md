# V4.2 事件整理与阅读使用指南

状态：2026-09-16 V4.2 剩余功能已交付，2026-09-26 用户统一验收通过（核心功能无明显问题）；首批真实样本仍未确认。先看[统一验收说明](V4_2_ACCEPTANCE.md)，下方保留操作参考。

2026-09-15 使用方式澄清：这一步服务于产业介绍，让收集到的消息变成“谁在什么时候做了什么”的可阅读条目，并能点回来源、修正错误。它不要求分析事件的原因、影响或未来趋势；这些属于 V5。

代理先准备具体成果和内容核对说明，并完成技术检查；用户主要看介绍是否清楚、来源是否便于找到，并对确实需要确认的内容作决定。下方表单步骤是操作参考，不是要求用户逐项执行的测试清单。现有内容确认规则仍适用，代理演示不能冒充用户确认。

## 入口

从项目根目录启动现有应用：`uvicorn app:app --reload`。

- `/events`：所有状态的事件台账，可按赛道、组织、人物与状态筛选。
- `/events/review`：统一成果入口；`/events/materials`：补充原文；`/events/extract`：从 RSS 拟候选；`/events/{id}/merge`：预览重复事件合并。
- `/events/new`：选择库内材料并创建事件候选。
- `/events/{id}`：事件摘要、研究问题、关联参与者、原始 RSS 摘录与修改记录。
- `/events/{id}/edit`：增补材料、修改字段、确认、标记待补证据或归档。
- `/timeline`：只显示已确认且有明确人工确认标记的事件，支持参与者/赛道筛选。
- 现有赛道页已提供事件台账与组织时间线入口，三个一级导航不变。

## 内容确认与修改的操作参考

1. 在台账打开事件，先阅读原始 RSS 摘录及证据边界，需要时打开原始来源。
2. 点击“编辑／确认／纠错／归档”。核对标题、事件类型、日期精度和参与者；文档发布时间不自动等于事件发生日。
3. 若证据确实支持事件基本发生，选择“已确认”，明确勾选核对确认，并填写确认原因。证据不足就保留候选或待补证据，不为填充时间线而确认。
4. 生成只读预览，检查变更前后与关联材料，再点击保存。预览尚未写库；版本或材料变化会拒绝保存，需重新预览。
5. 到时间线打开事件，检查是否能回溯到材料。日期未知的事件排在末尾，不填造日期。
6. 需要纠错时再次编辑并填写原因。若仍要保留已确认状态，必须再次勾选确认；若无法确认，改为候选、待补证据或有争议。修改记录保留前后内容。
7. 重复或不适合的事件可归档，退出确认时间线而不删除来源和日志。新增相关材料可在同一事件中继续勾选关联，不必每篇文章创建一个事件。

代理负责整理实际发生的使用记录：材料、确认或暂缓原因、来源查找和修改中的问题；用户用自然语言反馈即可，不需另填验收报告或自行计时。只能记录观察到或用户提供的时间与体验，未发生的复用留待后续，不能推算为已验证收益。技术纠错演练在临时库由代理完成，无需用户为通过测试而修改真实内容。

## 当前边界与维护

- RSS 摘录仍按需映射为 documents；另可选择已有手工摘录和官网正文。官网读取、材料保存、AI 提取都是各自明确操作，事件保存不会隐式抓取或调用 AI。
- AI 中文摘要与评分不作为原始证据。来源发布者不自动等于具体观点表达者；表单不自动关联企业领导人。
- 同一文档可供多个事件引用，事件编辑不覆写其原始快照。文档 ID、URL 或身份冲突会拒绝保存，不能静默关联其他文章。
- 已有专门合并和按需 AI 提取，均不自动确认；手工粘贴按摘录保存，官方网页按正文快照保存。暂无自由文件上传、无人审核、网页定时采集或自动事件合并。
- 新部署需先备份再显式执行项目迁移 CLI 的 `up` 命令；事件页面不会自动迁移。活动库本轮已有 0007，不需再次导入样本或重新建表。
- 聚焦测试：`python -m unittest tests.events.test_event_service tests.events.test_event_routes -v`；全套：`python -m unittest discover -s tests -v`。Windows 如遇子进程中文编码不一致，可在该终端设置 `$env:PYTHONUTF8='1'` 后重跑。
- 本轮写入前备份及迁移提前执行的异常记录见切片规格验收记录。备份是迁移后、样本写入前版本；不要把恢复整个数据库当作撤销单个事件的常规方式。
