## 1. 怎样使用这份清单

每个审核项都有稳定编号。你可以直接修改本文件里的复选框，也可以在对话中按编号回复。

每项可选择：

- `[x] 确认`：同意按当前草案写入。
- `[x] 需修改`：不同意当前内容，请在“修改意见”中写明。
- `[x] 暂缓`：本轮不写这一项，等待更多信息。

建议回复格式：

```text
整组确认：C-01～C-26、I-01～I-12
单项确认：O-01、O-02、P-01
需要修改：O-03，把……改成……
暂缓：R-05
最终写库授权：否
```

在最后的“Z-01 正式写库授权”勾选确认前，任何局部确认都不等于授权执行真实写库。

## 2. 先理解几个词

| 名词 | 本清单中的意思 |
|---|---|
| 稳定 ID | 程序长期识别对象的编号，例如 `openai`；以后显示名称改变，ID 也不跟着改变 |
| 规范名称 | 页面主要显示的正式名称 |
| 别名 | 搜索时可以命中同一对象的其他写法，不会创建第二个对象 |
| 目录占位 | 页面上显示赛道名称和“待建设”，但不填参与者、事件和档案内容 |
| 核查来源 | 用来证明组织身份、人物身份或任职关系的证据页面 |
| 跟踪来源 | 未来持续收集产业材料的来源身份，例如 OpenAI、Sam Altman |
| 来源入口 | 具体怎样获取材料，例如 RSS、官网页面或人工录入 |
| `official_verified` | 当前草案已有官方来源支持 |
| `secondary_verified` | 当前草案只有可靠二手来源支持 |
| `needs_primary_source` | 可以暂时保留，但仍需补一手来源 |
| `enabled` | 入口目前可以启用 |
| `planned` | 入口已规划，但尚未自动接入 |
| `manual` | 不自动抓取，由用户或整理流程手动录入高价值材料 |
